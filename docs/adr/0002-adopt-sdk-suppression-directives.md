# Adopt the SDK's fsharpanalyzer ignore directives as the escape hatch

The canonical no-comments policy says this analyzer "defines a suppression directive comment of its own (exact spelling decided in the analyzer project)". The decided spelling is FSharp.Analyzers.SDK's built-in mechanism, not an invented one: `// fsharpanalyzer: ignore-line|ignore-line-next|ignore-region-start|ignore-region-end|ignore-file NOCOMMENT001`. The `fsharp-analyzers` CLI and Ionide filter suppressed hits host-side (verified against 0.39.2), so a custom spelling would have required reimplementing range filtering the host already does, and editors would not have honored it. Consequences: `fsharpanalyzer:` is a baseline directive prefix (the suppression comment is itself a machine-read directive and never a violation), the analyzer reports every use of it as `NOCOMMENT002` at Warning severity so escape-hatch usage is visible in SARIF without failing the build, and the spelling is effectively frozen once the sweep lands in consuming repos.
