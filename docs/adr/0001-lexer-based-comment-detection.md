# Lexer-based comment detection instead of AST trivia alone

The obvious SDK-idiomatic detection path, `ParsedInput.Trivia.CodeComments`, silently misses `///` doc comments: the F# lexer routes exactly-three-slash comments to the XML-doc store instead of comment trivia, and an orphaned `///` (one not attached to any declaration) appears in no AST node at all. Since the no-comments policy bans `///` like any other comment, detection runs `FSharpSourceTokenizer` over the source and treats every comment-classified token as ground truth; trivia ranges are still used to group `//` and `(* *)` tokens into logical comments, and any comment token the trivia does not cover (the doc comments) is reported from the lexer sweep. Known accepted gap: comments inside conditional-compilation blocks that are inactive both for the project and for an empty-defines tokenizer pass are invisible to both mechanisms and go unreported.
