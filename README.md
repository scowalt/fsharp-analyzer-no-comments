# fsharp-analyzer-no-comments

An [FSharp.Analyzers.SDK](https://github.com/ionide/FSharp.Analyzers.SDK) analyzer that bans code comments. Every comment token (`//`, `///`, `////`, `(* ... *)`) is an error unless a policy exemption applies. Knowledge belongs in names, types, tests, docs, and git history — not in comments that rot.

Ships on NuGet as `Scowalt.NoCommentsAnalyzer`, with the analyzer DLL under `analyzers/dotnet/fs`. Works in CI via the [`fsharp-analyzers`](https://www.nuget.org/packages/fsharp-analyzers) tool and in-editor via Ionide.

## Diagnostics

| Code | Severity | Meaning |
|---|---|---|
| `NOCOMMENT001` | Error | A comment with no exemption. |
| `NOCOMMENT002` | Warning | A suppression directive is in use. Non-blocking; exists so escape-hatch usage is visible in SARIF and can be burned down. |
| `NOCOMMENT003` | Error | `no-comments.json` is invalid. The baseline policy applies until the config is fixed. |

## Exemptions

1. **Machine-read directives** — comments whose body begins (after optional whitespace) with a configured prefix. Baseline: `fsharpanalyzer:`.
2. **Generated files** — files whose first comment block (any comment before the first code token) contains `@generated`, `<auto-generated>`, or `<auto-generated/>` (case-insensitive), or whose path matches a generated glob. Baseline globs: `**/obj/**`, `**/bin/**`, `**/node_modules/**`, `**/schema.d.ts`.
3. **Shebangs** — line 1 of a file beginning `#!`.

`#nowarn` and other hash directives are compiler syntax, not comments, and are untouched.

## Suppression (emergency escape hatch)

The analyzer adopts the SDK's built-in ignore directives ([docs](https://ionide.io/FSharp.Analyzers.SDK/content/getting-started/Ignore%20Analyzer%20Hits.html)):

```fsharp
let x = request.Value // fsharpanalyzer: ignore-line NOCOMMENT001
```

Forms: `ignore-line`, `ignore-line-next`, `ignore-region-start` / `ignore-region-end`, `ignore-file`. Every use is reported as `NOCOMMENT002` (Warning). Treat each as a bug to burn down.

## Configuration

Optional `no-comments.json`, discovered by walking up from each analyzed file. Both keys append to the baseline; the baseline can never shrink. Unknown keys or wrong types are a `NOCOMMENT003` error.

```json
{
  "directivePrefixes": ["fsharplint:"],
  "generatedGlobs": ["src/Generated/**"]
}
```

Globs match the file path relative to the config file's directory (full path when no config exists), with `**`, `*`, and `?` semantics.

## CI wiring

```sh
dotnet tool install fsharp-analyzers
dotnet add package Scowalt.NoCommentsAnalyzer
dotnet fsharp-analyzers \
  --project YourProject.fsproj \
  --analyzers-path ~/.nuget/packages/scowalt.nocommentsanalyzer/<version>/analyzers/dotnet/fs \
  --report analysis.sarif
```

The tool exits nonzero on any Error-severity message, so `NOCOMMENT001`/`NOCOMMENT003` fail the build and `NOCOMMENT002` does not. For MSBuild-integrated runs see the [SDK's MSBuild docs](https://ionide.io/FSharp.Analyzers.SDK/content/getting-started/MSBuild.html); with `GeneratePathProperty="true"` on the package reference the analyzers path is `$(PkgScowalt_NoCommentsAnalyzer)/analyzers/dotnet/fs`.

## Mechanical stripping

`src/CommentStripper` is the sweep companion: a console tool that deletes every comment the analyzer would report as `NOCOMMENT001`, sharing the analyzer's detection, config discovery, and exemption logic so the two can never disagree. Directives, suppressions, generated files, and shebangs survive; comment-only lines are deleted, trailing comments are trimmed, and token separation is preserved. Run your repo formatter afterwards to normalize spacing.

```sh
dotnet run --project src/CommentStripper -c Release -- /path/to/repo/src /path/to/repo/scripts
```

It accepts files or directories (recursing into them, skipping `obj`, `bin`, `node_modules`, and `.git`), rewrites files in place, and exits nonzero if any `no-comments.json` on the walk is invalid.

## Development

```sh
dotnet build
dotnet test
dotnet tool restore
./scripts/smoke-test.sh
```

The smoke test runs the real `fsharp-analyzers` CLI against [`samples/Sample`](samples/Sample) (expects one `NOCOMMENT001`, one `NOCOMMENT002`, a host-filtered suppressed hit, and a nonzero exit) and then against this analyzer's own project, which must report zero violations.
